# Original CoDiscover Work Patterns

Use these as generative lenses, not as a checklist or evidence of effectiveness.

| Pattern | Useful when | Human checkpoint |
|---|---|---|
| Evidence brief | People must act on long or conflicting source material | Approve claims and source links |
| Exception queue | Routine cases obscure high-risk anomalies | Review thresholds and every escalated case |
| Decision ledger | Decisions and rationales disappear across meetings | Decision owner confirms status and rationale |
| Handoff contract | Ownership becomes unclear between roles or systems | Sending and receiving owners confirm acceptance |
| Assisted intake | Inputs arrive in inconsistent formats | Human verifies critical extracted fields |
| Triage and route | High volume requires prioritization | Human owns thresholds, appeals, and overrides |
| Draft and review | A first draft reduces effort but errors matter | Named reviewer approves before use |
| Compare and challenge | Teams anchor on one option too early | Decision owner reviews alternatives and dissent |
| Knowledge continuity | Context is lost across people, time, or agents | Owner validates what becomes reusable memory |
| Scenario rehearsal | Consequences should be explored before commitment | Human selects assumptions and interprets scenarios |
| Accessibility adaptation | One format or channel excludes participants | Affected users validate usability and alternatives |
| Learning loop | A workflow must improve from observed outcomes | Owner reviews evidence and decides Go/Revise/Stop |

Combine patterns only when each combination changes the workflow or control design. Avoid stacking labels without operational value.
