# Meta-Lab Learning Layer

Meta-Lab is an optional learning layer for comparing multiple completed CoDiscover design traces or experiments. It is not a required step in a single-case discovery response.

## Inputs and timing

Use Meta-Lab only when at least two case IDs, completed traces, or experiment records are available. Keep the delivery decision for each case separate from the learning claim about the portfolio.

## Learning questions

Compare cases through five lenses:

- **Repeat** — what recurs across cases;
- **Difference** — what changes by context, role, or boundary;
- **Surprise** — what contradicted the initial hypothesis;
- **Missing** — which evidence, voice, or control is still absent;
- **Reusable** — which pattern, template, or checkpoint can travel.

## Evidence ladder

Label every learning statement as one of:

1. **Observation** — directly visible in a case;
2. **Hypothesis** — a testable explanation;
3. **Emerging pattern** — repeated support across cases;
4. **Principle candidate** — a reusable rule that still needs wider testing.

Never call a single case a pattern or principle. A principle candidate must list its supporting cases and remain revisable.

## Two assets

Separate the outputs:

- **Delivery asset** — what a team can use now, such as a route, template, checkpoint, or experiment;
- **Learning asset** — what the system carries forward, such as a pattern card, evidence ledger, or new question.

Meta-Lab learns from traces; it does not silently rewrite the Core contract or freeze a fixed list of capabilities. Human owners decide what to reuse.
